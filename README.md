# Forte · Контроль кассы

Локальный сервис для ForteBank Datathon 26: принимает видео кассового узла, последовательно обрабатывает его и возвращает возможные нарушения с таймкодами и JPEG-кадрами. Интерфейс на русском, без сборки, CDN и внешних шрифтов. Распознавание лиц и идентификация людей не используются.

Корневой `fc_pipeline.py` — настоящая версия из `forte_pack_4b_v3`, скопированная без изменений (85 707 байт). Сервис вызывает только публичные интерфейсы `load_bundle`, `Video`, `ffprobe_duration`, `extract_frames`, `Analyzer.analyze` и `to_api`. Предыдущий модуль сохранён как `fc_pipeline_mock.py` и используется только при `MOCK_MODEL=1`; выбор модуля выполняется лениво в `app/model.py`.

## Быстрый запуск без GPU и весов

Нужны Python 3.10+ и `ffmpeg` / `ffprobe` в `PATH`. На Windows удобнее Python 3.11 или 3.12; Docker использует Python 3.10.

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements-service.txt
export API_KEY='replace-with-your-secret'
export MOCK_MODEL=1
sh run.sh
```

На Windows PowerShell:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python -X utf8 -m pip install -r requirements-service.txt
$env:API_KEY = 'replace-with-your-secret'
$env:MOCK_MODEL = '1'
.\.venv\Scripts\python -X utf8 -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1
```

Откройте `http://localhost:8000`. Выберите `.mov` / `.mp4`, нажмите «Проверить видео», дождитесь результата. Таймкоды перематывают исходную запись, кадры открываются в увеличенном виде. Если браузер не поддерживает кодек MOV, анализ по-прежнему работает; для просмотра нужен поддерживаемый браузером видеокодек.

В mock-режиме модель не загружается, `torch` не импортируется. `MockAnalyzer` ожидает 3–5 секунд, возвращает 1–2 **синтетических** события и три настоящих JPEG-кадра, полученных FFmpeg из загруженного видео. UI явно помечает этот режим. Mock не оценивает точность модели.

## Запуск с моделью на GPU

В проект установлен bundle из `forte_pack_4b_v3`: `decision.json` и `pipeline_config.json`. Реальный режим использует замороженный Qwen3-VL-4B и решающую модель на NumPy (`ChecklistAnalyzer`); LoRA-адаптер и `peft` не нужны. Пакет не содержит базовые веса Qwen — их необходимо заранее загрузить на сервер.

```text
bundle/
  pipeline_config.json
  decision.json
models/
  Qwen3-VL-4B-Instruct/
    config.json
    tokenizer_config.json
    ...все файлы модели, процессора и весов...
```

Установку зависимостей и перенос весов выполните до отключения интернета. Во время запуска сервис принудительно устанавливает `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`, `HF_HUB_DISABLE_TELEMETRY=1` и `DO_NOT_TRACK=1` **до** импорта библиотек модели. Облачных AI API в коде нет. Недостающие веса приводят к ошибке запуска, а не к скачиванию.

```bash
python -m venv .venv
. .venv/bin/activate
# Установите зависимости заранее, пока доступен интернет.
pip install -r requirements.txt
export API_KEY='test12345'
export HF_HOME='/workspace/hf'
export FORTE_BUNDLE_DIR='./bundle'
# Необязательно: полная локальная папка вместо модели из HF_HOME.
# export BASE_MODEL_PATH='./models/Qwen3-VL-4B-Instruct'
export LOAD_4BIT=1
unset MOCK_MODEL
sh run.sh
```

Путь bundle задаётся в `app/model.py`: `FORTE_BUNDLE_DIR`, затем совместимая прежняя переменная `BUNDLE_DIR`, затем `./bundle` относительно рабочей папки. Нужны оба JSON-файла; папка `adapter/` не требуется. `BASE_MODEL_PATH` поддерживается самим новым `load_bundle`: конфигурация не копируется и не изменяется. Без этой переменной используется `cfg.model_id` (`Qwen/Qwen3-VL-4B-Instruct`) из уже заполненного cache в `HF_HOME`. Поставляемый `pipeline_config.json` побайтово совпадает с обновлённым файлом команды: `cfg.max_windows` увеличен с 40 до 72, исправлены `rule_ref` для `unsafe_money`, `stranger_coming` и `client_handling`. Остальные настройки сохранены. Бюджет сканирования остаётся 190 секунд, общий дедлайн сервиса — 270 секунд.

Зависимости реального режима находятся в `requirements.txt`: `torch`, `transformers==4.57.6`, `accelerate`, `bitsandbytes>=0.46.1`, а также NumPy/Pillow из `requirements-service.txt`. `torchvision` оставлен для процессора изображений Transformers. FFmpeg и ffprobe должны быть установлены в системе до запуска. `peft`, pandas и openpyxl для этого пути инференса не устанавливаются.

### RunPod: терминал Jupyter

Используйте GPU-образ с установленными Torch/CUDA и `transformers==4.57.6`. Загрузите `forte_deploy.zip` в `/workspace`; полная модель, процессор и токенизатор должны уже находиться в cache `/workspace/hf`.

```bash
cd /workspace
unzip -o forte_deploy.zip -d forte
API_KEY=test12345 sh /workspace/forte/deploy/start_on_pod.sh
```

Скрипт определяет проект по собственному расположению, поэтому его можно вызывать из любой папки и запускать повторно. `API_KEY` берётся только из окружения; без него скрипт завершается до установки или перезапуска. При отдельной локальной папке модели добавьте к команде `BASE_MODEL_PATH=/workspace/models/Qwen3-VL-4B-Instruct`.

Сначала выполняется `python -m pip install --break-system-packages -r requirements.txt` с временным constraints-файлом, закрепляющим уже установленные версии `torch` и `torchvision`. Версии читаются через метаданные пакетов, без импорта Torch и инициализации CUDA. Torch не переустанавливается, установленный `transformers==4.57.6` сохраняется; при конфликте зависимостей установка завершается ошибкой. Отсутствующие FFmpeg/ffprobe устанавливаются через `apt-get install -y ffmpeg`.

Затем скрипт останавливает старый `uvicorn app.main:app`, дожидается его завершения и запускает один uvicorn worker через `nohup` на `0.0.0.0:8000`. Он задаёт `HF_HOME=/workspace/hf`, `FORTE_BUNDLE_DIR=<проект>/bundle`, `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1` и убирает `MOCK_MODEL`. Готовность проверяется до 120 секунд через публичный `/health` (`model_loaded=true`); при ошибке выводятся последние 30 строк `<проект>/service.log`. Этот же файл содержит журнал запущенного сервиса.

Установка недостающих зависимостей и FFmpeg может потребовать сеть; работа сервиса и загрузка уже сохранённых весов выполняются в offline-режиме. Для запуска с полностью отключённой сетью после подготовки зависимостей используйте ручную команду ниже.

Архив собирается из корня репозитория командой `python -X utf8 deploy/build_package.py`. В него входят только `app/`, `bundle/`, `deploy/`, два модуля пайплайна, `requirements*.txt`, `run.sh` и `README.md`. Тесты, веса, задания, логи, кеши, другие ZIP и Dockerfile в архив не включаются; shell-скрипты упаковываются с LF и правами исполнения.

### Docker и ручной запуск

Dockerfile использует CUDA 12.8 + cuDNN runtime, Python 3.10, FFmpeg, согласованные CUDA-сборки `torch==2.9.1` / `torchvision==0.24.1` и `transformers==4.57.6`. GPU-проверка требует настоящего GPU и весов; в этой среде выполнены проверки mock-режима.

Если файлы сервиса лежат непосредственно в `/workspace`, зависимости и FFmpeg уже установлены, а полный cache модели находится в `/workspace/hf`, точная команда запуска RunPod **без доступа к интернету**:

```bash
cd /workspace
unset MOCK_MODEL
HF_HOME=/workspace/hf \
FORTE_BUNDLE_DIR=/workspace/bundle \
API_KEY=test12345 \
HF_HUB_OFFLINE=1 \
TRANSFORMERS_OFFLINE=1 \
sh ./run.sh
```

Для отдельной локальной папки весов добавьте перед `sh ./run.sh` переменную `BASE_MODEL_PATH=/workspace/models/Qwen3-VL-4B-Instruct`. Без неё нужны все файлы Qwen в cache `/workspace/hf`, включая процессор и токенизатор. В команде запуска нет `pip`, `apt`, `hf download` или других сетевых шагов; при неполных весах запуск завершится ошибкой. Модель на этой машине не запускалась.

```bash
docker build -t forte-cash-review .
docker run --rm --gpus all -p 8000:8000 \
  -e API_KEY='test12345' \
  -e BASE_MODEL_PATH=/models/base \
  -e LOAD_4BIT=1 \
  -v "$PWD/bundle:/app/bundle:ro" \
  -v "$PWD/models/Qwen3-VL-4B-Instruct:/models/base:ro" \
  forte-cash-review
```

Для mock в том же образе достаточно `-e MOCK_MODEL=1`; GPU и тома с весами не нужны. Для проверки без любой сети запустите образ с `--network none` и проверьте `/health` и API через `docker exec` внутри контейнера; публикация порта в этом режиме недоступна.

На RunPod используйте GPU Pod с этим образом, диском с моделью и bundle, HTTP-портом `8000` и перечисленными переменными. Для 4-bit загрузки нужен поддерживаемый bitsandbytes GPU. Выбор объёма VRAM и качество результатов зависят от конкретной модели, кадров и адаптера; реальную производительность нужно измерить на целевом сервере.

Запускайте **один uvicorn worker**. Несколько процессов создадут несколько моделей, независимые очереди и несовместимые реестры job_id. По контракту UI-эндпоинты не требуют API-ключа; при размещении сервера ограничьте доступ к UI на уровне вашей сети или reverse proxy.

## Обработка данных

Исходное видео и временные кадры находятся только в рабочей папке `TemporaryDirectory` внутри `jobs/uploads/`. После `done`, `failed`, исключения или тайм-аута они удаляются в `finally` **до** выдачи конечного статуса. При тайм-ауте или падении процесса сначала останавливаются обработчик и его дочерние FFmpeg-процессы, чтобы закрыть файлы на Windows. При запуске папка загрузок полностью очищается; из папок заданий старой версии также удаляются видео и временные файлы.

Сохраняется только `jobs/<id>/state.json`: JSON-результат с кадрами-доказательствами в base64. Он доступен через `GET /api/v1/jobs/{id}` до истечения TTL — по умолчанию 6 часов после завершения (`RESULT_TTL_SECONDS`), в том числе после перезапуска сервиса. После TTL результат удаляется. Endpoint для выдачи исходного видео отсутствует; превью в браузере использует локальный файл.

Видео не используются для обучения, не публикуются и не передаются третьим лицам. Инференс выполняется локально, внешние AI-сервисы и телеметрия отключены. В журнал обработки пишется только `job_id`; содержимое, исходные имена файлов, stderr FFmpeg и traceback модели в логи не попадают. При принудительном завершении всего сервиса ОС не гарантирует выполнение Python `finally`, поэтому остатки удаляются до приёма запросов при следующем запуске.

## API

### Загрузка

```bash
curl -sS -X POST http://localhost:8000/api/v1/analyze \
  -H "X-API-Key: $API_KEY" \
  -F 'file=@short.mov;type=video/quicktime'
```

```json
{"job_id":"0123456789abcdef0123456789abcdef"}
```

Принимается ровно один multipart-файл `file`, расширение `.mov` или `.mp4` без учёта регистра, до 200 МиБ (209715200 байт). Файл сохраняется порциями; также ограничен общий multipart body, включая запросы без Content-Length. Обычные записи кейса до 145 секунд поддерживаются; отдельного ограничения длительности нет. Пустой файл / неправильное расширение / multipart → `400`, слишком большой файл → `413`. Повреждённое видео принимается в очередь, затем получает `failed`.

### Опрос

```bash
curl -sS http://localhost:8000/api/v1/jobs/0123456789abcdef0123456789abcdef \
  -H "X-API-Key: $API_KEY"
```

```json
{"job_id":"0123456789abcdef0123456789abcdef","status":"processing"}
```

```json
{
  "job_id":"0123456789abcdef0123456789abcdef",
  "status":"done",
  "verdict":"violation",
  "violations":[{
    "type":"Нарушение кассовой дисциплины",
    "timecode_sec":12.5,
    "description":"Возможное нарушение; требуется проверка человеком.",
    "evidence_frames":[{"timestamp_sec":12.5,"image_base64":"...JPEG в обычном base64..."}]
  }]
}
```

При отсутствии событий: `"verdict":"no_violation","violations":[]`. На каждое событие возвращается 1–3 JPEG-кадра; у base64 нет `data:`-префикса. `score`, `rule_ref`, `type_key`, английские описания и служебные поля в `/api/v1` не попадают.

```json
{"job_id":"0123456789abcdef0123456789abcdef","status":"failed","error":"Превышен лимит 270 с с начала загрузки, включая ожидание в очереди. Повторите попытку."}
```

Отсутствующий или неверный `X-API-Key` → `401` JSON. Проверка использует `hmac.compare_digest` и выполняется до чтения файла. Неизвестный / истёкший id → `404`. Ошибки запросов возвращаются как `{"error":"..."}`.

Пример полного цикла с `curl` и Python, без `jq`:

```bash
JOB_ID=$(curl -fsS http://localhost:8000/api/v1/analyze \
  -H "X-API-Key: $API_KEY" -F 'file=@short.mov' \
  | python -c 'import json,sys; print(json.load(sys.stdin)["job_id"])')
while true; do
  curl -fsS "http://localhost:8000/api/v1/jobs/$JOB_ID" \
    -H "X-API-Key: $API_KEY" -o result.json
  STATUS=$(python -c 'import json; print(json.load(open("result.json"))["status"])')
  [ "$STATUS" != processing ] && break
  sleep 2
done
cat result.json
```

`GET /health` доступен без ключа:

```json
{"model_loaded":true,"gpu_name":null,"queue_length":0}
```

На GPU `gpu_name` содержит имя устройства. `queue_length` — число ожидающих заданий, без активного задания и истёкших записей. UI использует `/ui/analyze` и `/ui/jobs/{id}` с теми же правилами; в завершённом UI-ответе каждое событие дополнено только `score` и `rule_ref`. `/ui/config` сообщает, включён ли mock. Swagger/ReDoc отключены, поэтому скрытых CDN-запросов нет.

## Архитектура

```text
видео MOV/MP4 → FFmpeg: 2 кадра/с → окна по 8 секунд
    → локальный Qwen3-VL-4B: чек-лист из 18 вопросов
    → решающая модель decision.json → кластеры событий
    → описания, таймкоды, 1–3 evidence JPEG → API / русский UI
```

В FastAPI lifespan запускается отдельный процесс с одной загруженной моделью. `app/worker.py` явно использует `multiprocessing.get_context("spawn")` на Linux и Windows, независимо от системного метода по умолчанию. Родительский процесс FastAPI не загружает модель и не инициализирует CUDA; имя GPU приходит из дочернего процесса. Единственный поток `gpu-fifo-worker` потребляет `queue.Queue` и последовательно передаёт задания этому процессу. Модель переиспользуется между заданиями; после принудительной остановки по тайм-ауту или падения процесса она загружается заново для следующего задания. Расчёты модели и MockAnalyzer не изменены. Все загруженные задания немедленно получают `processing`, включая ожидающие. Исключение конкретного задания не останавливает FIFO-поток. Данные защищены блокировкой; поздний результат не меняет `failed` обратно на `done`.

Отдельный монитор каждые 0.1 с проверяет общий дедлайн 270 секунд **с начала HTTP-загрузки**, включая сохранение и очередь. Опрос также проверяет дедлайн перед выдачей статуса. Проверка дедлайна не зависит от скорости модели. Уже истёкшие задания в очередь модели не запускаются.

Исходник и кадры размещаются в `jobs/uploads/<id>-<случайный суффикс>/`, а результат — отдельно в `jobs/<id>/state.json`. Вложенный `TemporaryDirectory` ограничивает расположение кадров `extract_frames`. Успешное завершение, ошибка и отмена завершаются удалением всей временной рабочей папки. Windows Job Object / POSIX process group позволяет завершить также FFmpeg, если основной процесс обработки упал. Монитор обнаруживает остановку FIFO-потока и удаляет его незавершённые загрузки. При запуске результаты восстанавливаются из JSON; незавершённые задания получают `failed` без сохранения исходника. Периодическая уборка удаляет истёкшие результаты; GET также проверяет TTL. Папка `jobs/uploads/` выделена только под временные данные и целиком очищается при старте.

## Тестирование

```bash
pip install -r requirements-dev.txt
MOCK_MODEL=1 API_KEY=test-secret python -X utf8 -m pytest -q
```

Все тесты работают без весов/GPU. Проверяются авторизация, точные поля API/UI, JPEG/base64, 404, типы и размеры файлов, очередь и параллельные загрузки, восстановление после исключения, дедлайн активного и ожидающего задания, включение времени загрузки в дедлайн, удаление исходника/кадров при каждом исходе, очистка мусора при старте, сохранность результата после перезапуска и его TTL. Отдельно проверяется остановка FFmpeg с открытым видео при тайм-ауте и падении процесса. Есть интеграционные проверки настоящего MockAnalyzer с FFmpeg и задержкой 3–5 секунд. На Windows запускайте Python с `-X utf8`.

Проверки интеграции v3 подменяют загрузчик: настоящие веса/GPU не загружаются. ## Модели и лицензии

Базовая модель v3 — **Qwen3-VL-4B-Instruct**, Apache-2.0 ([официальная карточка](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct)). Bundle может использовать другую модель; её размер и лицензию команда должна проверить перед подстановкой. Версия v3 использует `decision.json` без LoRA. В корневом архиве `forte.zip` пакет находился как вложенный `forte_pack_4b_v3.zip`; из него взяты только модуль и два JSON-файла, инструменты обучения в сервис не добавлялись.

Зависимости приложения имеют разрешительные лицензии: FastAPI, uvicorn, python-multipart, accelerate, bitsandbytes, pytest — MIT; Transformers и httpx — Apache-2.0 или BSD соответственно; PyTorch/torchvision, NumPy, psutil — BSD; Pillow — разрешительная HPND. Телеметрия отключена в соответствии с [документацией Hugging Face](https://huggingface.co/docs/huggingface_hub/package_reference/environment_variables).

**Противоречие в условиях лицензирования:** обязательный по ТЗ FFmpeg не выпускается под MIT/Apache/BSD: это системный инструмент LGPL-2.1+ / GPL в зависимости от сборки ([официальные условия FFmpeg](https://ffmpeg.org/legal.html)). Ubuntu-пакет может включать GPL-компоненты. CUDA runtime и драйвер NVIDIA также имеют собственные условия. Сервис не добавляет библиотеки распознавания лиц, облачные SDK или иные модели. Абсолютное требование «все компоненты только MIT/Apache/BSD» несовместимо с обязательными FFmpeg и CUDA; это исключение нельзя устранить заменой Python-зависимостей.

## Типы нарушений и нормативные источники

Типы и тексты источников настоящего режима поставляются в `bundle/pipeline_config.json`. Для `unsafe_money`, `stranger_coming` и `client_handling` используются обновлённые `rule_ref` из приложенного файла команды; остальные типы сохранены из v3. Команда проверяет применимость нормативных ссылок перед сдачей. Демо-типы используются только MockAnalyzer.

| `type_key` | Название | Наблюдаемые признаки | Нормативный источник / пункт |
| --- | --- | --- | --- |
| `leaving_workplace` | Уход с рабочего места | По чек-листу модели | Из `bundle/pipeline_config.json` |
| `unsafe_money` | Деньги и ключи без защиты | По чек-листу модели | Из `bundle/pipeline_config.json` |
| `stranger_coming` | Клиент без удостоверения, посторонний у рабочего места, незакрытая дверь | По чек-листу модели | Из `bundle/pipeline_config.json` |
| `client_handling` | Нарушение порядка работы с клиентами и деньгами | По чек-листу модели | Из `bundle/pipeline_config.json` |
| `other` | Прочее подозрительное действие | Неуверенный выбор типа | Требуется проверка по внутренним документам банка |
| `cash_outside_work_area` | Наличные вне рабочей зоны (только mock) | Синтетический сценарий | Заполняет команда |
| `cash_handover_check` | Проверка передачи наличных (только mock) | Синтетический сценарий | Заполняет команда |

UI отображает «Правило / источник» только при непустом `rule_ref`. Для внешнего API исходный `to_api(raw)` может дописывать правило в `description`, не добавляя новых JSON-полей.

## Ограничения и известные ошибки

- Это помощь проверяющему: возможны ложные срабатывания, пропуски и ошибки описания. Оценка 0–100 не является юридической оценкой или калиброванной вероятностью. Для реальных метрик нужны GPU, веса, независимая выборка и проверка специалистом.
- Контекст вне кадра, документы и фактические банковские проводки недоступны. Качество зависит от камеры, освещения, перекрытий и локализации события. Личности людей сервис не устанавливает.
- По дедлайну останавливается изолированный процесс инференса вместе с дочерними FFmpeg-процессами, затем удаляются временные данные и публикуется `failed`. Для следующего задания модель загружается заново; время загрузки также учитывается в его общем дедлайне. Ошибки драйвера/ОС, которые не позволяют завершить процесс или удалить файл, требуют вмешательства администратора; сервис не выдаёт `done` до удаления временных данных.
- В v3 бюджет сканирования проверяется между окнами в `ChecklistAnalyzer.scan`, но не прерывает отдельный вызов модели и не включает последующие описания. Поэтому общий лимит 270 секунд контролирует существующий процесс-супервизор.
- В актуальном предоставленном `fc_pipeline.py` уже используется устойчивая функция `sigmoid`. При изменении жизненного цикла данных пайплайн не редактировался.
- Пустое/повреждённое видео, отсутствие видеодорожки и очень короткая запись без извлечённых кадров дают `failed`. Кодек может поддерживаться FFmpeg и не поддерживаться браузером.
- Несколько uvicorn workers не поддерживаются. JSON-результаты восстанавливаются при старте и хранятся до TTL; видео и промежуточные кадры после завершения не сохраняются. Уборка результатов выполняется примерно каждые 30 секунд, а GET сразу возвращает `404` для истёкшего результата. В карточке события оценка модели размещена под заголовком и таймкодом, перед описанием; информация о хранении в UI обновляется отдельно.
- Docker-сборка и настоящий GPU-инференс требуют отдельной проверки на целевой машине. Зависимости и веса должны быть установлены заранее для работы без сети.

Результат — подсказка для проверки человеком, а не юридическое заключение.
